# 复盘并上报这场会话

WorkBuddy 的会话 coach 读不到，所以这一步由**你**来做：回看这场对话，挑出卡点，
交给 CLI 落盘。CLI 负责 id、格式和密钥扫描 —— **不要自己手写 Markdown 卡片。**

## 1. 先列候选，不落盘

回看这场对话，挑出最多 5 条值得沉淀的卡点。只挑这四类：

| type | 什么样的 |
|---|---|
| `pitfall` | 同一个错反复出现、改了好几次才对、用户纠正了你 |
| `playbook` | 一段试错式排查，最后找到了路 |
| `pattern` | 一个做法被验证有效，下次还能照用 |
| `concept` | 一个之前没弄清、这次弄清了的概念 |

每条给出：标题、type、为什么挑中它、**证据**。证据只能是这场对话里真实出现过的
`文件:行号`、命令原文、报错首行 —— **没有就留空，不要编。**

把候选列给用户，然后只问一句：

> 这几条里，哪几条值得记下来？

## 2. 他挑了之后再上报

只上报他挑的那几条。用带引号的 heredoc，JSON 里的引号和 `$` 才不会被 shell 吃掉：

```
node {{COACH}} report --host workbuddy --cwd "<当前项目目录>" <<'EOF'
[
  {
    "title": "一句话标题",
    "type": "pitfall",
    "why": "为什么挑中它",
    "evidence": ["src/a.ts:42", "npm test", "TypeError: x is undefined"],
    "ai": "为什么会这样（你的解释）",
    "transfer": "下次遇到这类问题的第一步",
    "tags": ["typescript"]
  }
]
EOF
```

把命令输出原样贴给他。

## 3. 认领 —— 这一步必须是他的话

上报的卡是 `status: inbox`，「我自己的表述」一节是空的。请他用**自己的话**说一遍
这条到底意味着什么，然后逐字存进去（流程见 `coach-kb-save` skill）：

```
node {{COACH}} save --id <id> --stdin <<'EOF'
他的原话，逐字
EOF
```

## 三条禁令

1. **不要替他写那句话。** 不给例句、不替他填、不润色。
2. **不要不问就上报。** 落盘必须由他开口。
3. **不要编证据。** 对话里没出现过的文件名、行号、报错，一个字都不要写。
