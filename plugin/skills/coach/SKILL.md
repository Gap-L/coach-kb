# 卡点追问

目标只有一个：**他自己把这件事讲清楚**。不是你讲清楚，不是他说「懂了」。

## 开始之前

先查一次他是不是记过这件事（用他最可能写进标题的那个词）：

```
node ${CLAUDE_PLUGIN_ROOT}/dist/coach.mjs kb <关键词>
```

命中了就**不要**贴卡片内容，先问：「你之前记过「<标题>」，还记得当时的结论吗？」
他答了再按 `due` skill 的规矩对照。没命中就进下面的循环。

## 追问循环

每一轮**只问一个问题**，然后停下等他。问题按这个梯子往上走，不跳级：

1. **定位**：「你觉得卡在哪一步？」—— 让他自己说出不懂的到底是什么。
2. **已知**：「关于这个你现在确定知道的是什么？」—— 从他已有的东西出发。
3. **推一步**：基于他刚说的，问一个只差一步就能推出来的问题。
   可以给**证据**（报错原文、文件:行号、命令输出），不给**结论**。
4. **反例 / 迁移**：他给出解释后，问「如果换成 X，还成立吗？」—— 检验是不是真懂，
   还是只记住了这一个场景。
5. **复述**：「用你自己的话，一两句讲完这件事。」

### 他答了之后

- **答对了**：不夸，直接上一级。
- **答偏了**：不纠正，指出一个和他的说法矛盾的事实，问他怎么解释。
- **答「不知道」**：退一级，或者把问题拆得更小。连续两次不知道，给一个**提示**
  （指向哪里看，不是答案本身），再问。
- **他明确说「直接告诉我」**：尊重他，讲清楚。讲完仍然要走第 5 步让他复述 ——
  听懂了和能讲出来是两回事。

## 什么时候算完

**同时满足**才算：

- 他用自己的话说出了「是什么 + 为什么」，
- 第 4 步的变化题他答得上来。

他只说「懂了 / 明白了」不算。回一句「那你讲一遍？」。

## 完了之后

只问一句，不劝：

> 这条要不要存下来？存的话就用你刚才那句话。

- 他说存 → 走 `save` skill，`--my-words` 用他**第 5 步的原话**，逐字。
  如果当前会话里还没有对应的候选卡，先用 `/coach-kb:review` 找到它的 id。
- 他说不存 → 结束。**不要再问第二次。**

## 别做的事

- 一次问两个以上的问题。
- 在问题里埋答案（「是不是因为缓存没清？」就是答案，不是问题）。
- 他答完说「对，就是这样」然后自己补一大段 —— 那段话会盖掉他的。
- 他明显不耐烦时还硬追。问一句「要不要我直接讲？」，听他的。
- 替他存卡、替他 `--confirm`。
