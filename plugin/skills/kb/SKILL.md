# 查知识库

知识库是**用户自己的 Markdown 文件**，不是你的记忆。你要做的是把命令的输出给他看，
而不是凭印象回答「我记得你之前记录过……」—— 你没记过，卡片记过。

## 按他问的选一条

| 他问的 | 跑 |
|---|---|
| 「关于 X 我记过什么」 | `node ${CLAUDE_PLUGIN_ROOT}/dist/coach.mjs kb <关键词>` |
| 「把那张卡给我看」 | `node ${CLAUDE_PLUGIN_ROOT}/dist/coach.mjs kb --show <id>` |
| 「我知识库里都有啥」 | `node ${CLAUDE_PLUGIN_ROOT}/dist/coach.mjs kb --list` |
| 「哪些还没认领」 | `node ${CLAUDE_PLUGIN_ROOT}/dist/coach.mjs kb --inbox` |
| 「哪些卡我一直没补自己的话」 | `node ${CLAUDE_PLUGIN_ROOT}/dist/coach.mjs kb --stale` |

多条关键词**不要**拼在一起猜，就用他最可能写进标题的那个词。
搜不到就直说搜不到，然后建议换个词 —— 不要为了显得有用而列出不相关的卡。

## 展示的规矩

`kb --show <id>` 直接把卡片 Markdown 原文打出来。**原样贴。** 卡片是给人读的，
它分四节，每节各有各的用途：

- `## 我自己的表述` —— 他当时写的原话。**这一节是卡片的全部价值。**
- `## AI 补充与纠正` —— 只是补充，不是主体。
- `## 证据` —— 文件:行号 / 命令 / 报错原文，来自真实会话。
- `## 下次这类问题的第一步` —— 可执行的那一条。

贴完以后，如果他接着问「这条讲的是什么」，**不要用你的话解释 `## 我自己的表述`** ——
那等于把他写的东西再译一遍，还译不准。直接把那一节念给他，或者问他当时是想解决什么。

## 一个提醒（说一次就够，别念叨）

`kb --stale` 列出来的卡是**躺了 3 天以上、他自己那句话一直没补**的。
那几行现在只是 AI 摘要，不是他的知识。看到了可以提一句：

> 这几张躺了几天了，还是 AI 写的。要不要挑一张，你自己说一句？`/coach-kb:save`

他不接话就算了。**这张单子是给他自己看的，不是给你催的。**
