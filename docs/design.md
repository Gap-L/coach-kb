# 设计记录

> 这份文档记的是**为什么这么做**,不是怎么用。用法看 `coach --help`。
> 每条设计决策下面都跟着它要挡的那个具体失败 —— 没有失败场景的"最佳实践"不算理由。

## 一句话

让 AI 干过的活变成**你自己的**知识。

## 唯一成败指标

**你自己写的那句话有没有出现。**

不是"沉淀了多少条",不是"覆盖率",不是"知识库多大"。是这个:

```markdown
## 我自己的表述            ← 你写的,逐字,不摘要
## AI 补充与纠正            ← 只补「为什么」和「可迁移到哪」
## 证据                    ← 直接来自会话:文件:行号 / 命令 / 报错原文
## 下次这类问题的第一步
```

这四节里,**只有第一节是 AI 写不出来的**。其余三节 AI 都能替你写,
而正因为能替你写,它们单独存在时没有任何价值 —— 那只是又一份 AI 摘要。

所以整套东西都在保护这一节:

| 机制 | 挡的是什么 |
|---|---|
| `status` 默认 `inbox`,不自动 `confirmed` | 卡片悄悄变成"已完成",而那句话一直没写 |
| `save` 要求原话,拒绝占位符(`待补`/`n/a`/`-`) | 用"我明白了"这种话把位置占了 |
| `save` 太短会当场提示(但不拒绝) | 一周后你自己看不懂 —— 提示,不替你写 |
| `kb --stale` 专门列躺了 3 天还没补表述的卡 | 它们看起来在知识库里,其实只是 AI 摘要 |
| `doctor` 把"缺你自己那句话"的数报成 ⚠ | 这个数涨上去时没人注意到 |

最后一条是这套设计里唯一真正的风险:如果哪天 `save` 变得**可以用**,
而用户不需要真的想清楚任何事,这个项目就失败了 —— 它会退化成又一个
"AI 帮我总结了一下"的工具。

## 三个动词的边界

分得这么细是为了让"落盘"这件事**永远需要一个有意识的动作**。

| 动词 | 干什么 | 落盘吗 |
|---|---|---|
| `review` | 看这场会话里有哪些卡点。只列候选 | **不落盘** |
| `distill` | 把卡点落成半成品卡(骨架 + AI 补的「为什么」) | 落,但 `status: inbox` |
| `save` | **用你自己的话认下它** | 这一步它才算数 |

`review` 输出里会印一句「这些还都不是知识,只是候选」,并且 `--save`
是显式的另一条路 —— 不让"看一眼"顺手变成"存进去"。

## 核心设计原则:落盘的触发必须来自确定性来源

这是本项目最重要的一条教训,来自旧 coach 的一个已经定位的 bug。

旧 coach 的落盘闸门是 `register.tsx:353` 的一行自由文本正则:

```ts
if (t !== null && t.phase === 'execute' && done > 0 && DEBRIEF_RE.test(spoke)) {
```

只有模型**逐字**写出「下次…先看什么」那句,笔记才会落盘。用对模型自由文本的
正则匹配当闸门,等于把沉淀的可靠性外包给模型的自觉。结果:

- `~/.claude/coach/notes/` 至今为空
- 状态文件的 stats 是 `{tasks: 0, notes: 0}`
- 而且**失败是静默的**:没有报错,只是文件夹一直空着

所以本项目的规则是:**模型只用来说明「为什么」,不用来保证「有没有记录」。**
哪些卡点值得记,由 `core/signals.ts` 从会话日志里确定性地抽;
模型只负责补两件它才擅长的事。

## 热路径预算

`UserPromptSubmit` hook 在**每次回车**时跑。这是整个项目里唯一一个
用户能直接感觉到快慢的地方,所以它有硬预算:**< 100 ms**。

实测(本机 macOS / darwin 27.0.0,`node dist/hook.mjs`,12 次取均值;
会话为合成的 64.0 MB / 71,831 行 jsonl):

| 场景 | 均值 | 最大 |
|---|---|---|
| 事件不匹配(Stop)→ 立刻返回 | 22.5 ms | 24.9 ms |
| 64 MB 会话(71,831 行)尾部解析 | 23.8 ms | 30.2 ms |
| 64 MB 会话 + 用户纠正措辞 | 22.9 ms | 24.7 ms |

**结论:node 冷启动(~22 ms)就是地板,64 MB 的尾部读只加了约 2 ms。**
最坏 30.2 ms,离 100 ms 还有 3 倍余量。这个预算里能做的事非常少,
所以 hook 里只有:哨兵检查 → 读 stdin → 读 transcript **尾部** N KB →
一张正则表 → 一行输出。**LLM 永不在 hook 里跑。**

三道护栏:

1. `budgetMs()`(默认 80 ms)超了就放弃 —— 提醒是可选的,卡顿不是
2. `hooks.json` 里 `timeout: 3`(秒)是外层兜底。默认是 30 秒,
   而 `readFileSync(0)` 在 stdin 是没人关的管道时会一直等 —— 3 秒是给那种情况留的
3. 异常全吞,永远 `exit 0`。**`exit 2` 会把用户的 prompt 拦下来不发**,
   那比不提醒严重得多

## 一个踩了两次的坑:`readHead`

`readFileSync(p, 'utf8').slice(0, N)` 看起来只读 N 字节,**其实整个文件都进了内存**。

这个坑在本项目里踩了两次:`sessions.ts` 的 `readCwd`(抠 cwd)和
`parse.ts` 的 `readHeader`(读头部)。两处都在 hook 的路径上,
而本机有一场 52 MB 的会话 —— 实测 `--latest` 因为这一行从 1.16 s 掉到 0.11 s。

修法是把两处并成 `core/lines.ts` 的 `readHead`,只留一份实现。同一个坑踩两次
说明它不值得靠"下次注意"来防,所以现在有两条护栏:

- **`test/lines.test.ts` 的 rss 断言**:32 MB 文件上调 8 次 `readHead`,
  rss 增量必须 < 4 MB。正确实现实测 +0.4 MB,退化成整文件读是 +32 MB 量级 ——
  中间隔着一个数量级
- **源码级 lint**:`src/` 下不许再出现 `readFile(Sync)(...).slice(` 这个形状

### 为什么断言 rss 而不是 heapUsed

这条踩过坑:Bun 里**字符串和 Buffer 不计入 `heapUsed`**。
实测同一个 32 MB 的全量读,`heapUsed` 涨 0.0 MB,而 `rss` 涨 32.5 MB。
拿 `heapUsed` 去断言等于什么都没测 —— 测试全绿,而 bug 原样在。

(当时先发现了这件事才写出有效的断言。正向对照:`Buffer.alloc(32MB).toString()`
是 heap 0.0 MB / rss +64.3 MB,而一个 JS 数组是 heap +32 MB。)

## 为什么没有 Stop hook

`UserPromptSubmit` 挂了,`Stop` **故意没挂**。

需求里「会话结束自动复盘」是被明确划掉的(用户觉得烦)。而 Stop 事件上:

- 普通 stdout **到不了模型**(只进 debug log),要说话必须用
  `hookSpecificOutput.additionalContext`
- 所以"在 Stop 上温柔地提醒一句"在技术上等于用 `additionalContext` 注入

那就是把被排除的东西换个名字加回来。既然用户排除的是**行为**而不是**通道**,
这里就不该绕过。所以 `Stop` 上什么都没挂,而不是挂一个"很克制"的。

(挂着的 `UserPromptSubmit` 提醒仍然符合已确认的"卡点即时提醒":它只在
高精度信号上触发 —— 同一个错误 ≥2 次、或用户纠正 + 动过文件 —— 
**不是** `repeat_edit` 那种噪声,而且有节流:最小间隔 600 s、每天最多 6 次、
每个 key 冷却 24 小时,并且可以整个关掉。)

## 为什么前缀是 `[coach-kb]` 而不是 `[coach]`

旧 dev-mod 往上下文里钉的正是 `[coach] 阶段 A:…`,用的词也是「先别动文件」。

两边都叫 coach 的话:模型会把沉淀层的提醒读成提问层的阶段指令,
而用户看到两条同样开头的话也无从分辨是谁说的。**共存的前提是先分得清。**

## 为什么插件必须自包含

`${CLAUDE_PLUGIN_ROOT}` 在从 git / url / npm 装的插件上指向**缓存副本**,
不是源码仓。而"插件目录之外的文件不会被拷进去"。于是:

- 路径里带 `..` 会被 `claude plugin validate` 直接判为路径穿越
- 即使本地路径装(就地加载)能读到 `../dist`,同一个插件被同事从 git 装上时
  就会静默失效 —— 一个"装好了但不生效"的坑

所以 bundle 复制进 `plugin/dist/`,让插件自包含。`scripts/build.mjs` 负责同步,
`test/plugin.test.ts` 钉住它。

## 为什么 skill 的 `allowed-tools` 要和正文对得上

skill 正文是给模型看的**指令**,`allowed-tools` 是**权限**。两者一脱节,
表现是:模型照着正文跑,然后停下来问用户要权限 —— 而用户正看着一个"教练"卡在半路。

这个坑真出现过:`save` 的正文让人跑 `kb --confirm`,而 `save` 只放行了 `save …`。
所以现在有 `test/plugin.test.ts` 里那条断言:**正文里出现的每个 coach 子命令,
都必须被本 skill 放行**。

同理,正文和权限里必须用**同一个** `${CLAUDE_PLUGIN_ROOT}` ——
一边写变量另一边写死路径,规则永远不命中。

## 复习排期:为什么索引不认兜底规则

复习这条腿原来只有交互、没有排期 —— `review.next` 全仓没有任何写入方。
于是 `kb --due` 只能退回「落卡满 7 天」,复习过的卡第二天照样到期(永远到期),
而 `index.md` 的「该复习了」永远是空的。现在
`coach kb --reviewed <id> --recall <档>` 把用户自己定的那个档写进
`review_count` / `review_last` / `review_next`。

阶梯在 `src/core/review.ts`。是**查表不是算术** —— `7,14,30,60,120` 不是翻倍序列(14→30 而非 28):

| 用户说的 | 下次复习 | 连续次数 |
|---|---|---|
| 稳了 | 7 · 14 · 30 · 60 · 120(第 5 次起封顶) | +1 |
| 模糊 | 3 天 | 不变 |
| 没想起来 | 1 天 | 归零 |

`count` 封顶之后继续涨 —— 它是真实的连续次数记录,封顶的只是间隔。
「模糊」不动 `count` 是刻意的:惩罚它会让人不敢承认自己模糊,那个档就没意义了。

**三处容易改错的地方,都有测试钉着:**

1. **兜底规则必须让位。** `bootstrapDue` 要排除已经有 `review.next` 的卡。
   一张 10 天前落的卡刚定了「稳了」,如果还按落卡日期算,它明天又被算成到期 ——
   正是这次要修的病。
2. **索引只认排期,`kb --due` 才带兜底。** 两者对「从没定过档的卡」会正当地显示不同的列表。
   让 `index.md` 也吃兜底,等于让一个属于用户的文件在他什么都没做时自己变响 —— 那是 nag。
   兜底是一次交互命令里的提示,不是一份常驻清单。
   将来想让它变响,改 `renderIndex` 一行即可,但那该是它自己的决定。
3. **闸门是 `confirmed`,不是「到期」。** 没认领的卡谈不上复习,但**提前复习必须允许** ——
   别加「没到期不许记」。

写入只用 `setFmLine` 逐行替换 frontmatter,**不整文件重渲染** —— 和 `upsertCard`
同一个理由:这条路径永远不许碰 `## 我自己的表述`。判成败用「读回来对不对」,
**不用**「字符串变没变」(`setStatus` 那套):同一天连记两次「模糊」三个值完全相同,
后者会把一次成功报成「改不动」。

档位只有一个来源 —— 用户自己说的那个词。AI 只负责问、然后把那个词原样传进去,
不许替他判断(见 `plugin/skills/due/SKILL.md` 的「别做的事」)。

## 已解决:验收脚本的脱敏 grep 太粗

> 现在 `coach doctor` 的「知识库」一节会用 `scanRedaction` 逐卡扫盘上的真实文件
> (`scanKbLeaks`),按密钥形状匹配,`«REDACTED:…»` 不会误报;命中即 ✗,只报规则名不回显原文。
> 下面保留原始记录。

规划文档里的验收命令是:

```bash
grep -rE 'sk-|ghp_|AKIA|ANTHROPIC_AUTH_TOKEN' /tmp/coach-kb
```

这条在**知识库里含脱敏夹具文本**时会误报 —— 卡片正文里出现
«REDACTED:api_key» 这类标记是正确行为,不是泄露。真要自动化,
得匹配"真实的密钥形状"而不是这几个前缀词。目前 `coach doctor`
的 canary 自检(12 条)是更可靠的替代。
